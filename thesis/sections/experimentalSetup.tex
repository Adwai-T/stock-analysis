The hardware specifications become important as the libraries used and thus the training time can be heavily impacted by the hardware being used. In my case as I was using AMD RX580 as the GPU which is not supported by tensorflow that is used in this project as library for training and most other popular libraries with good support, all the training was mostly completed on the CPU.

Even though most training could use CPU, GPU could speed up training time significantly in most cases by many times. This becomes especially significant when larger  models, like transformer or CNN LSTM models trained on all companies data, it took significant time upwards of hours to complete. Where as if GPU acceleration were used with the CUDA cores of Nvdia, it could have been significantly reduced.

\section{Kite Connect API}

Zerodha provides the Kite Connect API as a tool for developer to build custom trading applications. It offers real time order exectuttion and portfolio management. But more important to this project, they provide live stock market data streaming for equities, commodities and MF's.

Their api can be implemented directly as HTTP API requests with any language of choice but in this case I have used the opensource API helper that is provied by Zerodha for python that helps directly pull data from thier APIs.

\begin{lstlisting}[language=bash, caption=Installing KiteConnect, basicstyle=\ttfamily\small]
pip install kiteconnect
\end{lstlisting}

The complete documntation for this could be found at 

\begin{lstlisting}[language={}, caption=KiteConnect GitHub Repository URL]
https://github.com/zerodha/pykiteconnect
\end{lstlisting}

\section{Authentication process}

In this program that I have created I have used a python script that help go through the authentication process which will generate a request token.

The request token is used to authorize any changes to the users account and his portfolio.

Running \texttt{\textbf{\textit{python scripts/generate\_access\_token.py}}} to generate Access Token that needs to be refereshed everyday. This is then stored in credentials file in the root of the project and can be used for further requests.

It is important to make sure that this file is not shared online and does not get included in the github repo so should be excluded as it contains sensitive information about the kite connect account that could to make unwanted transactions.

\begin{lstlisting}[language={}, basicstyle=\ttfamily\small, caption=API Credentials Configuration]
{
  "API_KEY": "",
  "API_SECRET": "",
  "ACCESS_TOKEN": "",
  "REQUEST_TOKEN": ""
}
\end{lstlisting}

\section{Getting Historical Data}

I used a script that would get each companies stock historical data and store in the data folder so that it could be used later in any combination to train models as needed.

Following are the different configuration of paramenter that could be used with the Kite Connect API

\subsection{Historical Data Endpoint}

\begin{description}
    \item[\textbf{Method}] GET
    \item[\textbf{Endpoint}] \texttt{/instruments/historical/\{:instrument\_token\}/\{:interval\}}
    \item[\textbf{Description}] Retrieve historical candle records for a specified financial instrument.
\end{description}


\subsection{Path Parameters}

\begin{description}
    \item[\textbf{:instrument\_token}]  
    Unique identifier of the financial instrument for which historical data is requested.  
    This value is obtained using the \texttt{instrument list} endpoint.

    \item[\textbf{:interval}]  
    Specifies the time interval of each OHLCV candle record.  
    Supported values include:
    \begin{itemize}
        \item \texttt{minute}
        \item \texttt{day}
        \item \texttt{3minute}
        \item \texttt{5minute}
        \item \texttt{10minute}
        \item \texttt{15minute}
        \item \texttt{30minute}
        \item \texttt{60minute}
    \end{itemize}
\end{description}


\subsection{Query Parameters}

\begin{description}
    \item[\textbf{from}]  
    Defines the start of the historical window using  
    the format \texttt{yyyy-mm-dd hh:mm:ss}.

    \item[\textbf{to}]  
    Defines the end of the historical window using  
    the format \texttt{yyyy-mm-dd hh:mm:ss}.

    \item[\textbf{continuous}]  
    Accepts \textbf{0} or \textbf{1}.  
    Set to \textbf{1} to retrieve continuous historical data streams.

    \item[\textbf{oi}]  
    Accepts \textbf{0} or \textbf{1}.  
    When set to \textbf{1}, the response includes \textbf{Open Interest (OI)} data.
\end{description}
